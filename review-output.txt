# 覃远的思想杂货店（Hexo + Stellar 博客）代码审查报告

## 总体结论
**站点健康度：良好（有隐患）**

*   **优点**：文章内容完美契合"Hardy 真实人设第一人称、敢讲失败"的松弛调性，可读性极高。配置文件的职责划分清晰，样式引入支持异步加载，CDN 图片使用了 WebP 参数（`?imageMogr2/format/webp/quality/85`）进行性能优化，具备优秀的工程实践。
*   **隐患**：存在 1 处由于 Stellar 标签未闭合导致的**构建致命错误**，以及若干影响多平台兼容性、SEO 及精细排版的警告，亟需修正。

## 问题详情列表

### 🔴 严重（会导致构建失败或线上故障，必须修复）

#### 1. Stellar `quot` 标签未成对闭合
*   **受影响文件**：`source/_posts/migrate-notionnext-to-stellar.md`（第 46 行）
*   **问题描述**：文章末尾使用了自定义标签 `{% quot 无论用... %}`，但未添加闭合标签。Stellar 主题规范中，`quot` 标签**必须成对闭合**，否则 `hexo generate` 会在构建时抛出模板渲染错误，导致 Vercel 部署失败。
*   **具体修复建议**：
    将：
    ```markdown
    {% quot 无论用什么方案、什么主题，最重要的还是内容，以及持续的输出。希望自己能一直做到。 %}
    ```
    修改为标准的成对块级语法：
    ```markdown
    {% quot %}
    无论用什么方案、什么主题，最重要的还是内容，以及持续的输出。希望自己能一直做到。
    {% endquot %}
    ```

---

### 🟡 中等（影响体验 / SEO / 性能，建议修复）

#### 1. 资源文件使用了中文命名
*   **受影响文件**：
    *   物理路径：`source/images/博客主页.png`
    *   引用位置：`source/_posts/migrate-notionnext-to-stellar.md`（第 44 行）
*   **问题描述**：在网页端使用中文字符作为图片文件名，在不同的操作系统（如本地 Windows、GitHub 的 Git 存储、Vercel 部署的 Linux 环境）之间传输时，极易因 UTF-8 字符集规范化（NFC/NFD）冲突或 URL 编码不一致导致线上图片 **404 无法加载**。
*   **具体修复建议**：
    1. 将文件 `source/images/博客主页.png` 重命名为 `source/images/stellar-homepage.png`。
    2. 将文章内的引用修改为：
       ```markdown
       {% image /images/stellar-homepage.png "焕然一新的 Stellar 主题博客首页" %}
       ```

#### 2. 文章 Front-matter 中 `date` 字段缺少具体时间
*   **受影响文件**：`source/_posts/xianyu-earn-168.md`（第 3 行）
*   **问题描述**：该文章的 `date` 仅配置为 `2026-08-08`，缺少了时分秒。根据项目 `GEMINI.md` 规范与 Hexo 的解析原理，未指定时间会导致 Hexo 解析时默认将其归入当天的 `00:00:00`，在不同时区环境（如 Vercel 构建容器时区设为 UTC）中部署时，极易发生时区漂移导致前台显示的文章日期变为前一天（`2026-08-07`）。
*   **具体修复建议**：
    将：
    ```yaml
    date: 2026-08-08
    ```
    修改为符合 YYYY-MM-DD HH:mm:ss 格式的具体时间：
    ```yaml
    date: 2026-08-08 12:00:00
    ```

#### 3. 导航栏网格列数与实际项目数不匹配
*   **受影响文件**：`_config.stellar.yml`（第 6 行）
*   **问题描述**：配置项 `menubar.columns` 设置为 `4`，但下方 `items` 中实际配置了 `5` 个导航项（博客、分类、标签、归档、关于）。这会导致 Stellar 主题在基于 CSS Grid 渲染导航栏时产生布局错乱或最后 1 项强制折行。
*   **具体修复建议**：
    将：
    ```yaml
    menubar:
      columns: 4
    ```
    修改为匹配的列数：
    ```yaml
    menubar:
      columns: 5
    ```

#### 4. 文章内链使用了不安全的非加密 `http://` 协议
*   **受影响文件**：
    *   `source/_posts/notionnext-vercel-blog.md`（第 52 行）
    *   `source/_posts/free-ai-assistant.md`（第 23 行）
*   **问题描述**：引导用户回访自己博客的链接使用了 `http://qinyuan.me`。由于站点已配置 HTTPS（正式域名 `https://qinyuan.me`），使用 HTTP 会导致额外的重定向，且不符合现代站点的安全策略。
*   **具体修复建议**：
    将所有的 `http://qinyuan.me` 替换为安全的 `https://qinyuan.me`。

#### 5. 性能隐患：本地大图缺乏 CDN 级 WebP 压缩
*   **受影响文件**：
    *   `source/_posts/migrate-notionnext-to-stellar.md`（第 14、44 行）
    *   `source/_posts/xianyu-earn-168.md`（第 26 行）
*   **问题描述**：与使用 COS 的 CDN 优化图不同，本地引用的图片如 `image.jpg`、`博客主页.png`（高分辨率截图）是原始大图。未经压缩的 PNG 可能会达到数 MB 大小，严重拖慢 Vercel 静态页面的首屏加载速度。
*   **具体修复建议**：
    建议将这些图片同样上传至腾讯云 COS 并在文章中使用带压缩参数的 CDN 链接（例如：`https://img.qinyuan.me/images/stellar-homepage.png?imageMogr2/format/webp/quality/85`），或者在提交仓库前使用 TinyPNG 等工具对本地图片进行深度压缩。

### 🟢 建议（风格 / 一致性优化，可选修复）

#### 1. 中文排版中使用英文直引号 `""`
*   **受影响文件**：
    *   `source/_posts/xianyu-earn-168.md`（第 8、35、44 行）
    *   `source/_posts/notionnext-vercel-blog.md`（第 14 行）
    *   `source/_posts/free-ai-assistant.md`（第 13、15 行）
*   **问题描述**：在中文语境段落中混用了英文直角双引号 `"折腾服务器"`、`"买了就走"`，不符合中文排版美学。
*   **具体修复建议**：
    将其修改为标准的中文双引号 `“折腾服务器”`、`“买了就走”` 或角括号 `「折腾服务器」`、`「买了就走」`。

#### 2. 中英文、数字之间混淆了半角空格（盘古之白）
*   **受影响文件**：
    *   `source/_posts/xianyu-earn-168.md`（多处数字，如 `30元`、`14单`）
    *   `source/_posts/notionnext-vercel-blog.md`（标题：`0基础`）
*   **问题描述**：中英文或数字交界处，有时有空格（如 `3 个月`、`168 元`），有时无空格（如 `30元`、`0基础`），格式不一致影响阅读连续性。
*   **具体修复建议**：
    统一在汉字与英文/数字之间插入一个半角空格，例如：`30 元`、`0 基础`、`NotionNext + Vercel`。

#### 3. 滥用加粗语法代替 H3 标题
*   **受影响文件**：`source/_posts/free-ai-assistant.md`（第 25、39 行）
*   **问题描述**：在 `## 两个真实使用场景` 下方，使用加粗的 `**从零搭出一个带域名邮箱的个人博客**` 充当小标题。这会导致页面无法自动生成正确的 H3 目录大纲（TOC），且不利于 SEO 权重分配。
*   **具体修复建议**：
    将这些加粗段落改为正规的 Markdown H3 标题：
    ```markdown
    ### 从零搭出一个带域名邮箱的个人博客
    ```

#### 4. 临时审查日志未被 Git 忽略
*   **受影响文件**：`.gitignore`
*   **问题描述**：根目录下产生的文件 `review-err.txt` 和 `review-output.txt` 为本地工具产物，未在 `.gitignore` 中声明，有被误提交到 Git 仓库的可能。
*   **具体修复建议**：
    在 `.gitignore` 末尾添加一行：
    ```
    review-*.txt
    ```

## 优先修复顺序

建议按照以下优先级逐一修复，可保证构建流程通畅，同时提升站点的跨平台稳定性与首屏加载速度：

1. **第 1 步：修复 🔴 严重问题 1** (修改 `migrate-notionnext-to-stellar.md` 中的 `{% quot %}` 标签，确保能顺利通过 `hexo generate` 构建)。
2. **第 2 步：修复 🟡 中等问题 1** (重命名 `博客主页.png` 为英文路径，规避 Vercel 404 风险)。
3. **第 3 步：修复 🟡 中等问题 2、3、4** (补全文章日期时分秒、适配 `_config.stellar.yml` 导航列数、一键替换 HTTP 为 HTTPS)。
4. **第 4 步：修复 🟡 中等问题 5** (对本地图片进行 WebP 化或离线压缩，优化博客加载体验)。
5. **第 5 步：根据个人审美偏好微调 🟢 建议问题** (排版引号、盘古之白空格、H3 标题转换、以及补充配置 `.gitignore` 过滤日志)。
